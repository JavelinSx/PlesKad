# Настройка автообновления законов (Google Sheets + Google Search + GitHub Actions)

## 1. Создайте Google-таблицу

1. Откройте [sheets.google.com](https://sheets.google.com) → «Пустой файл».
2. Назовите таблицу, например «ПлесКад — изменения в законах».
3. Переименуйте нижнюю вкладку (лист) с «Лист1» на **`laws`** (обязательно именно так — скрипт обращается к листу по имени `laws!A:H`).
4. В первой строке сделайте заголовки (необязательно, но удобно — скрипт сам распознаёт и пропускает строку заголовков, если ячейка A1 равна `date`): `date | title | summary | details | source | link | manual_summary | manual_details`. Название столбцов можно менять как угодно — скрипт читает их по позиции (A, B, C...), а не по названию.
5. Скопируйте **ID таблицы** из адресной строки браузера:
   `https://docs.google.com/spreadsheets/d/ЭТОТ_ДЛИННЫЙ_ID/edit` — вам нужна именно эта часть между `/d/` и `/edit`.

## 2. Создайте сервисный аккаунт в Google Cloud

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) (войдите тем же Google-аккаунтом).
2. Вверху создайте новый проект (или выберите существующий) — например, «pleskad-laws».
3. В поиске сверху введите **"Google Sheets API"** → откройте → нажмите **«Включить» (Enable)**.
4. Слева в меню: **IAM и администрирование → Сервисные аккаунты** (IAM & Admin → Service Accounts).
5. **«Создать сервисный аккаунт»**:
   - Имя: например `laws-updater`
   - Роль можно не назначать (доступ дадим напрямую через саму таблицу на шаге 3)
   - Нажмите «Готово»
6. Откройте созданный сервисный аккаунт → вкладка **«Ключи» (Keys)** → **«Добавить ключ» → «Создать новый ключ» → тип JSON**.
7. Скачается `.json`-файл — это и есть `GOOGLE_SERVICE_ACCOUNT_JSON`. **Никому не показывайте и не коммитьте его** — он даёт доступ к таблице.
8. В этом файле есть поле `"client_email"` вида `laws-updater@ваш-проект.iam.gserviceaccount.com` — оно понадобится дальше.

## 3. Дайте сервисному аккаунту доступ к таблице

1. Откройте вашу Google-таблицу (шаг 1) → кнопка **«Настройки доступа» / «Share»** справа сверху.
2. Вставьте туда `client_email` из JSON-файла (шаг 2.8).
3. Права — **«Редактор» (Editor)**. Нажмите «Отправить»/«Готово» (уведомление на почту сервисному аккаунту слать не нужно — можно снять галочку).

## 4. Настройте поиск (Google Custom Search)

Скрипт сам ищет свежие законы через настоящий веб-поиск (не RSS) — это реальные результаты с реальными ссылками, без выдумывания.

1. В том же проекте Google Cloud (шаг 2) в поиске введите **"Custom Search API"** → откройте → **«Включить»**.
2. Слева: **API и сервисы → Учётные данные (Credentials)** → **«Создать учётные данные» → «Ключ API»**. Скопируйте — это `GOOGLE_SEARCH_API_KEY`.
3. Откройте [programmablesearchengine.google.com](https://programmablesearchengine.google.com/controlpanel/create) → создайте новую поисковую систему.
4. В настройках поисковой системы, в разделе **«Сайты для поиска»**, добавьте по одному:
   - `pravo.gov.ru`
   - `rosreestr.gov.ru`
   - `consultant.ru`
   - `garant.ru`

   Так поиск будет вестись только по официальным/юридическим источникам, а не по случайным блогам. Список можно менять здесь же, в любой момент, без правки кода.
5. На странице поисковой системы найдите **«Идентификатор поисковой системы» (Search engine ID)** — это `GOOGLE_SEARCH_CX`.

Бесплатный лимит — 100 запросов в день; скрипт делает 6 запросов за прогон, так что даже ежедневный ручной перезапуск не приблизится к лимиту.

## 5. Добавьте секреты в GitHub-репозиторий

Откройте [github.com/JavelinSx/PlesKad](https://github.com/JavelinSx/PlesKad) → **Settings → Secrets and variables → Actions → New repository secret**. Добавьте пять секретов:

| Имя секрета | Значение |
| --- | --- |
| `GOOGLE_SHEET_ID` | ID таблицы из шага 1.5 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Всё содержимое скачанного `.json`-файла целиком (откройте его текстовым редактором, скопируйте весь текст, включая `{ }`) |
| `DEEPSEEK_API_KEY` | Ваш ключ с [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys) |
| `GOOGLE_SEARCH_API_KEY` | Ключ API из шага 4.2 |
| `GOOGLE_SEARCH_CX` | Идентификатор поисковой системы из шага 4.5 |

## 6. Проверка

1. В репозитории: вкладка **Actions → Update law changes feed → Run workflow** (запустить вручную, не дожидаясь начала месяца).
2. Если всё настроено верно — в логе будет видно, сколько результатов нашёл поиск и сколько из них выбрал DeepSeek, а в конце появится коммит с обновлённым `data/laws.ts` (или сообщение «No changes», если ничего нового не нашлось).
3. Если упадёт с ошибкой — почти наверняка это опечатка в одном из пяти секретов или лист таблицы назван не `laws`.

## 7. Ручное редактирование записей (приоритет над DeepSeek)

Каждая строка в таблице — это один закон. Столбцы **C (summary)** и **D (details)** заполняет DeepSeek автоматически. Если хотите поправить формулировку вручную — не трогайте C/D, а заполните:

- **Столбец G** (`manual_summary`) — своя короткая фраза вместо автоматической.
- **Столбец H** (`manual_details`) — своя расшифровка. Если нужен один абзац — впишите текст в одну ячейку. Если нужен список по пунктам — впишите каждый пункт на **новой строке внутри той же ячейки** (в Google Sheets: `Alt+Enter` на Windows или `⌘+Enter` на Mac для переноса строки без выхода из ячейки).

Если столбец G или H заполнен — при следующей пересборке сайта он полностью заменит собой автоматическую версию для этой строки (столбцы C/D при этом никуда не пропадают, просто не используются, пока G/H не очищены). Строка `date`, `title`, `source`, `link` (A, B, E, F) при этом не меняется — правится только текст описания.

Правки в G/H попадут на сайт при следующем запуске workflow (раз в месяц, либо запустите вручную через **Actions → Run workflow**, не дожидаясь этого — тогда `data/laws.ts` пересоберётся сразу с учётом правок, даже если новых законов не найдётся).
